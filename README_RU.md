# Каздойбы — исправление турниров и обновлённый интерфейс

Версия 1.4.0. Это обновление вашего существующего проекта Node.js, Render и Supabase.

**Если версия 1.3 уже установлена, выполните новый SQL-файл `supabase/004_tournament_reliability.sql`, затем обновите весь проект на Render. Если предыдущие SQL-файлы не выполнялись — примените `001`, `002`, `003`, `004` по порядку. Одной замены `public` недостаточно.**

## Новое в версии 1.4

- Ходы людей и ботов в турнирах рассчитываются и проверяются на сервере. Работа бота больше не зависит от браузера организатора или игрока. Устаревшие и повторные ходы отклоняются с обновлением позиции.
- Расчёт вынесен в отдельные рабочие потоки с ограничением времени и очереди. При ошибке расчёта партия приостанавливается; после паузы можно нажать «Продолжить партию». Оставшееся на момент паузы время сохраняется.
- В турнире можно выбрать лёгких, средних или сложных ботов. Организатор может изменить уровень до начала турнира.
- При истечении времени таймер показывает `00:00`. Появляется экран результата: «К турнирной сетке», «Главная», «Посмотреть доску». Выход по первым двум кнопкам освобождает комнату.
- В разделе «Турниры» появились вкладки «Текущие» и «История». Организатор может удалить завершённый или отменённый турнир; участник — скрыть его только у себя.
- Отдельные разделы: «Главная», «Играть», «Турниры», «Друзья», «Профиль», «Настройки», «Поддержка». Убраны повторяющиеся пояснения, увеличен мелкий текст, сокращены карточки игроков на телефоне.

Источники реализации: `tournament-play.js`, `turn-pool.js`, `game-engine.js`, `public/network.js`, `public/match-ui.js`, `public/arena.js`, `public/app.js`, `public/app.css`, `supabase/004_tournament_reliability.sql`. Результаты локальных проверок и их ограничения описаны в `QA_RU.md`.

## Что сделать в Supabase

Откройте **существующий проект**, в котором уже работает авторизация и сохранение партий.

1. Откройте **SQL Editor → New Query**.
2. Вставьте весь файл `supabase/001_social.sql` и нажмите **Run**.
3. В новом запросе вставьте весь файл `supabase/002_arena.sql` и нажмите **Run**.
4. В новом запросе вставьте весь файл `supabase/003_room_seating_avatars.sql` и нажмите **Run**.
5. В новом запросе вставьте весь файл `supabase/004_tournament_reliability.sql` и нажмите **Run**.
6. Убедитесь, что запросы завершились без ошибок, затем переходите к обновлению сервера.

Пропустите уже успешно выполненные файлы `001`–`003`. Для обновления с версии 1.3 достаточно шага 5 — нового файла `004`.

Эта последовательность использует штатный SQL Editor: [инструкция Supabase](https://supabase.com/docs/guides/database/functions#getting-started).

`001_social.sql` создаёт таблицы друзей, сообщений и приглашений. `002_arena.sql` создаёт таблицы турниров и добавляет `rating_mode` в существующую таблицу `matches`. `003_room_seating_avatars.sql` добавляет сохранение аватара и рассадки турнирного матча, а также серверные функции управления. Старые записи `matches` получают значение `rated`. Скрипты не удаляют игроков, историю или переписку; повторное применение проверено тестами.

`004_tournament_reliability.sql` добавляет уровень ботов и персональное скрытие турниров, обновляет серверную функцию управления турнирами. Существующие турниры получают средний уровень. Применение миграции само по себе не удаляет историю; удаление выполняется только отдельным действием организатора.

Новые таблицы закрыты для прямых обращений браузера. Доступ осуществляется через Node.js: сервер проверяет пользователя, затем вызывает функции базы со служебным ключом. Не нужно вручную открывать RLS-политики для всех пользователей или включать Supabase Realtime — уведомления идут через существующий Socket.IO-сервер.

Скрипты рассчитаны на существующие таблицы `players`, `matches`, `match_players`, `moves` и Supabase Auth из вашего проекта. Они не являются установкой исходной игры в пустую базу. Схема вашего работающего сервиса удалённо не проверялась; если запрос выдаст ошибку, сохраните её текст и не переходите к публикации кода до устранения причины.

1. Распакуйте архив. Загрузите содержимое папки `Kazdoyby_Public-main` в корень того же репозитория GitHub, который подключён к Render. `server.js` и `package.json` должны остаться на прежнем уровне.
2. Обновите **все** файлы проекта. Особенно нужны новые `game-engine.js`, `tournament-play.js`, `turn-pool.js`, `turn-worker.js`, `public/game-core.js` и остальные файлы из архива. Сохраните прежние переменные окружения на Render.
3. Сохраните изменения в GitHub. При включённом автоматическом развёртывании Render запустит обновление. Иначе откройте сервис и выберите **Manual Deploy → Deploy latest commit**. [Документация Render](https://render.com/docs/deploys#manual-deploys).
4. После успешного развёртывания перезагрузите страницу сайта, при необходимости — `Ctrl+F5`.

Для существующего Node.js Web Service команды могут остаться прежними: установка через `npm install` или `npm ci`, запуск через `npm start`. В `package.json` требуется Node.js 20 или новее. Новые серверные пакеты для работы игры не добавлялись; дополнительные пакеты в `devDependencies` используются тестами.

Существующие переменные окружения:

| Переменная | Значение |
| --- | --- |
| `SUPABASE_URL` | URL вашего проекта Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный publishable-ключ или прежний `anon`-ключ |
| `SUPABASE_SECRET_KEY` | Серверный secret-ключ или прежний `service_role`-ключ |

Если они уже правильно настроены, менять значения не нужно. Новые переменные окружения и отдельный Storage bucket для аватаров не нужны. Назначение типов ключей описано в [документации Supabase](https://supabase.com/docs/guides/getting-started/api-keys).

## Как пользоваться турнирами

1. Войдите в аккаунт и откройте «Турниры → Создать турнир».
2. Укажите название, число участников, время на матч — 3, 5, 10 или 15 минут — и сложность ботов. До начала турнира организатор может изменить сложность в карточке турнира и нажать «Сохранить».
3. Отправьте друзьям ссылку-приглашение или восьмизначный код. Они входят в аккаунт, открывают турнир и нажимают «Участвовать».
4. Организатор автоматически занимает одно место. Когда все места заполнены, он нажимает «Начать турнир».
5. Организатор нажимает «Управлять комнатой» у нужной пары; участники — «Войти в матч». Комната создаётся автоматически.
6. Организатор проверяет места, при необходимости меняет их нажатием на аватары и нажимает «Начать матч». Сам по себе вход двух игроков больше не запускает партию.
7. Победитель автоматически проходит дальше. Следующий матч доступен, когда определились оба его участника. Финал определяет чемпиона.

**Формат матча:** два назначенных сеткой соперника, у каждого — бот выбранного организатором уровня в команде. По умолчанию люди играют за синих и красных. Организатор может выбрать любой цвет, но перед стартом один соперник должен находиться в команде синих/чёрных, другой — красных/белых. Остальные места занимает ИИ. Это сохраняет четырёхсторонние правила вашей игры. Все турнирные партии проходят без изменения ELO.

При ничьей участникам предлагается переигровка той же пары. Кнопка «Сдаться» передаёт победу сопернику. Перезапуск и смена кода турнирного матча отключены. До начала турнира участник может отозвать участие; организатор может отменить турнир. Одновременно один аккаунт может организовывать до пяти незавершённых турниров.

После партии используйте «К турнирной сетке», чтобы открыть следующий матч, или «Главная». «Посмотреть доску» закрывает окно результата, оставляя завершённую позицию; кнопка возврата остаётся над доской. Когда записан результат финала, окно показывает завершение турнира и чемпиона.

### Удаление истории турнира

Откройте **«Турниры → История»**, затем нужный турнир. Организатор нажимает **«Удалить турнир»** и подтверждает удаление. Удаляются турнир, список участников и сетка для всех пользователей; история отдельных партий в профиле остаётся. Действующий турнир сначала нужно завершить или отменить.

Обычный участник видит **«Скрыть из истории»**. Это убирает турнир только из его списка и не меняет данные других участников. По известному коду скрытый турнир остаётся доступен. Автоматического восстановления скрытого элемента через интерфейс пока нет.

## Как организатору назначать места

1. В турнирной сетке нажмите **«Управлять комнатой»** у нужного матча. Если вы уже в этой комнате, откроется список участников. Во время просмотра другой комнаты переход доступен сразу; активную собственную партию нужно сначала завершить или покинуть.
2. Дождитесь подключения участников. Нажмите на аватар игрока за доской или в разделе «Наблюдатели».
3. Выберите нужный цвет или **«В наблюдатели»**. Если два игрока уже сидят за доской, выбор занятого места поменяет их местами после подтверждения. Если на занятое место садится наблюдатель, прежний игрок переходит в наблюдатели после подтверждения.
4. Верните обоих турнирных соперников в разные команды и нажмите **«Начать матч»**. Если не все нужные участники подключены, кнопка недоступна.

В турнирный матч можно посадить только двух соперников, назначенных сеткой: случайный зритель или организатор другой пары не может заменить их. Участник, временно переведённый в наблюдатели, остаётся участником турнира. Гость без аккаунта может смотреть, но для игры нужен вход в аккаунт. Изменения сразу видят все подключённые участники.

**После старта рассадка блокируется до конца партии.** Смена цветов или состава по ходу матча повлияла бы на определение победителя. Для следующего матча или переигровки рассадка снова доступна. Аватар можно менять и во время игры.

В обычной комнате права организатора принадлежат её создателю, даже если он стал наблюдателем. Кнопка «Участники» доступна над доской; до старта есть список участников комнаты. Права не передаются автоматически другому игроку при отключении создателя. Для старта обычной онлайн-партии также нужна кнопка «Начать матч».

## Как изменить аватар

Войдите в аккаунт, нажмите на свой аватар в профиле или откройте **«Настройки → Мой аватар»**. Выберите одну из 12 иконок либо **«Загрузить фото»**, настройте масштаб и положение кадра, затем нажмите **«Сохранить аватар»**.

Поддерживаются JPG, PNG и WebP до 5 МБ. В браузере фото обрезается до квадрата 256 × 256, преобразуется в JPEG и уменьшается до 50 КБ. Сервер проверяет тип и размер; внешние ссылки и SVG-файлы не принимаются. Вместо фото всегда можно снова выбрать иконку.

Аватар сохраняется в Supabase, поэтому остаётся после перезагрузки и входа с другого устройства. Он виден другим игрокам. Комната обновляет аватар сразу; открытый список друзей обновляется при следующем обновлении данных. Отдельное хранилище Supabase Storage создавать не нужно.

## Как пригласить наблюдателей

При создании обычной комнаты оставьте включённым «Разрешить просмотр по коду или ссылке». Нажмите «Ссылка для наблюдателя» и отправьте её зрителю. Ссылка имеет вид `https://ваш-сайт/?watch=КОД` и открывает просмотр без входа в аккаунт.

Также в окне онлайн-комнаты можно ввести код и нажать «Смотреть игру». У турнирных матчей наблюдение включено; ссылка доступна над доской, а кнопка просмотра — в турнирной сетке после создания комнаты. Количество зрителей показывается участникам. Установлен предел 100 одновременных подключений наблюдателей на комнату; это программное ограничение, не результат нагрузочного тестирования.

## Работа сервера и сохранение данных

Друзья, сообщения, аватары, заявки на участие, сетка, назначенные цвета и уже записанные результаты турниров сохраняются в Supabase. Тема и язык сохраняются отдельно в браузере; черновик сообщения сохраняется в памяти страницы при переключении между чатами.

Игровые комнаты, текущая позиция и присутствие пользователей остаются в памяти **одного процесса Node.js**, как в исходном проекте. Используйте один экземпляр игрового сервера. Обновляйте сервер между партиями: перезапуск закрывает активные комнаты. Для незавершённого турнирного матча кнопка входа создаёт новую комнату той же пары; текущая позиция автоматически не восстанавливается. Комната закрывается, когда уходит последний участник, включая наблюдателей. Поэтому выход всех игроков больше не выбрасывает оставшихся зрителей.

При кратком разрыве связи клиент пытается вернуться в прежнюю комнату, пока она существует. Участникам турнира сохраняются назначенные цвета; посторонний игрок не может занять место в этой паре. Таймер при отключении участника не останавливается.

**В турнирах** ходы рассчитываются и проверяются на сервере по общему с браузером модулю правил `public/game-core.js`. Клиент отправляет начальную и конечную клетки и номер версии позиции. Сервер проверяет очередь, роль игрока и законность хода. Отправка клиентом готовой позиции или победителя для турнира запрещена.

Боты используют целевые бюджеты поиска 180, 650 и 1400 мс для трёх уровней. Пул содержит максимум два рабочих потока, очередь — максимум 64 ожидающих задания; ожидание в очереди ограничено 5 секундами, один расчёт в рабочем потоке — 4 секундами. Это значения в `public/game-core.js` и `turn-pool.js`, **не гарантия времени ответа при любой нагрузке**. При срабатывании ограничения расчёта бот пробует допустимый ход без углублённого поиска; при неудаче или перегрузке партия приостанавливается. Рабочие потоки предназначены для выноса вычислений из основного потока Node.js: [документация Node.js](https://nodejs.org/api/worker_threads.html).

**Обычные онлайн-комнаты и офлайн-игра** продолжают использовать браузерный движок. Независимая серверная проверка всех правил добавлена только для турнирного режима.

## Пределы масштабирования

Готовность к 1 000 000 000 пользователей подтвердить нельзя: нагрузочное испытание такого масштаба не проводилось. Текущий проект рассчитан на один процесс игрового сервера; количество зарегистрированных аккаунтов и число одновременных партий — разные показатели. Новый пул ограничивает вычисления ботов, но не превращает сервер в распределённую систему.

Для дальнейшего роста потребуется отдельно реализовать распределение комнат между серверами, сохранение и восстановление активных позиций, ограничение входящей нагрузки и наблюдение за задержками, а затем измерить допустимую нагрузку. Сейчас нельзя включать несколько независимых экземпляров этого сервера и ожидать общей памяти комнат. Источники этих ограничений: `server.js` (`rooms = new Map()`), `turn-pool.js` и `tournament-server.js`.

## Что такое папка tests

`tests` содержит автоматические проверки для разработчика. Они проверяют, например, что посторонний не читает чужой чат, наблюдатель не делает ходы, только организатор меняет места и победитель правильно определяется после смены цветов. Игроки эту папку не видят; при `npm start` эти файлы не запускаются. Для обычной работы сервера папка не обязательна, но её полезно оставить в репозитории для будущих обновлений.

Для запуска проверок на компьютере разработчика:

```sh
npm ci --include=dev
npm test
```

Тесты используют локальный PostgreSQL-движок PGlite, тестовую схему и Socket.IO. Они не обращаются к вашему Supabase. Проверяются приватность переписки, роли пользователей, повторы сообщений, заявки и приглашения, недавние соперники, неизменность ELO, турнирная сетка, ничья, повторная запись результата, назначение и обмен мест, перевод в наблюдатели и обратно, запуск организатором, блокировка рассадки после старта, сдача игрока за белых с продвижением соперника за чёрных, сохранение аватаров и ограничения наблюдателей. Добавлены проверки серверных ходов, продолжения работы бота без браузера ведущего игрока, переподключения, уровня сложности и удаления/скрытия истории. Итог Node.js: 23 успешных тестовых узла, 0 ошибок; число включает родительские группы. Подробности — `QA_RU.md`.

В этой версии локально проверены в Chromium: турнир двух аккаунтов с шестью ходами людей и шестью ответами ботов, выбор сложности, завершение и удаление турнира, смена языка, профиль и темы. Отдельная проверка истечения серверного времени подтвердила `00:00` у обоих клиентов, окно результата, возврат к сетке/на главную и доступность переигровки при ничьей. Проверены мобильный экран шириной 390 пикселей, обычные офлайн-ходы, отмена, история, результаты по времени и сохранение состояния при смене языка.
